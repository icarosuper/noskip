# Architecture

> **How to use this file.** It answers *"which file do I open and what bites me there"*: flow
> between files, invariants that hurt to break, negative facts, and pointers to decisions. It does
> **not** list every function — `grep` does that for free and never goes stale. For "where is
> feature X", see [features-index.md](features-index.md).

## Layout

```
scripts/import/          → AnimeThemes importer (bun script, not part of the app bundle)
  animethemes-client.ts  → GraphQL client: pagination, rate limit, retries
  animethemes.ts         → CLI entry: upserts anime → song → artist → song_artist → theme
src/
  db/
    index.ts             → Drizzle client (node-postgres); throws if DATABASE_URL is missing
    schema/auth.ts       → GENERATED by the Better Auth CLI — never hand-edit
    schema/catalog.ts    → anime, theme, song, artist, song_artist (written only by the importer)
    schema/ratings.ts    → rating, review, review_report, favorite (top 10)
    schema/social.ts     → profile (bio + settings), follow
  lib/auth-options.ts    → Better Auth config, shared by the app and the test auth
  lib/auth.ts            → Better Auth server instance
  lib/auth-client.ts     → Better Auth React client
  lib/logger.ts          → pino logger: JSON on stdout, secrets redacted
  start.ts               → start instance: request log + request id, CSRF, server-fn error log
  router.tsx             → router defaults (not-found and error pages)
  components/            → app shell and shared UI pieces
  features/<feature>/    → queries.ts (Drizzle, takes `database`) + server.ts (thin server
                           functions) + components/ — vertical slices
  styles.css             → theme tokens (decisions.md #10)
  routes/                → file-based routes; thin: loader calls server functions, renders components
  routes/api/auth/$.ts   → Better Auth HTTP handler (OAuth callbacks, session endpoints)
  routes/health.ts       → health check server route (pings Postgres)
  integrations/          → TanStack Query provider/devtools (from the scaffold)
drizzle/                 → GENERATED SQL migrations (drizzle-kit)
```

There is **no API layer** besides server functions (`createServerFn`) and the Better Auth handler.
There is **no client-side data cache in use yet**: TanStack Query is wired by the scaffold but every
page loads through route loaders, and mutations refresh with `router.invalidate()`.

## Data flow

1. **Import (offline).** `bun run import:animethemes` pages through
   `graphql.animethemes.moe` (`animePagination`, 25 anime per page, themes/songs/artists nested in
   the same query) and upserts every row keyed by `animethemes_id`. Limits and terms:
   [data-sources.md](data-sources.md).
2. **Read.** Route loaders call server functions in `features/*/server.ts`, which query Postgres
   with Drizzle.
3. **Write.** Components call POST server functions (`rateTheme`, `saveReview`, `favoriteTheme`,
   `followUserFn`, `saveSettings`…), then `router.invalidate()` re-runs the loaders.
4. **Rank.** `getRanking` computes a bayesian average per theme on every request
   ([decisions.md #4](decisions.md#4-rankings-use-a-bayesian-average-computed-per-request)).

## Logging

`src/start.ts` registers the middleware every request goes through:

- **Request log:** one JSON line per request (`requestId`, method, path, status, `durationMs`), at
  `error` level when the status is 5xx. The id comes from an incoming `x-request-id` header or is
  generated, and is sent back in the `x-request-id` response header.
- **CSRF:** `createCsrfMiddleware` for server functions. TanStack Start adds it by itself only when
  there is no `start.ts`, so it must stay in this list.
- **Server-function errors:** logged with their stack and the function name. `notFound()` and
  `redirect()` are not logged. Server functions run through this during SSR too.

Log with `logger` from `#/lib/logger` (server code only), never `console.*`. `LOG_LEVEL` sets the
level (`info` by default). Where logs go is the host's business
([decisions.md #13](decisions.md#13-the-app-runs-on-any-node-host-jobs-run-outside-it)).

## Data model

```
anime 1──n theme n──1 song n──n artist   (song_artist carries credited_as)
                │
                ├──n rating n──1 user    (PK user_id + theme_id, score 1–10 by CHECK)
                │     └──0..1 review         (composite FK to rating: no review without a score)
                │            └──n review_report
                └──n favorite n──1 user  (position 1–10, unique per user → max 10)

user 1──0..1 profile   (bio, is_private, show_spoilers, show_nsfw; no row = defaults)
user n──n user         (follow: follower_id → following_id)
```

- **The rated entity is `theme`, not `song`**
  ([decisions.md #2](decisions.md#2-users-rate-a-theme-not-a-song)).
- `theme.type` is `OP | ED | IN`. **Only OP/ED are shown and rated in v0**: queries filter with
  `isRatedThemeType`, and the write paths refuse `IN` (`RatingError`). Insert songs are still
  imported.
- `theme.spoiler` / `theme.nsfw` come from AnimeThemes' entries: spoiler when every version is
  flagged, NSFW when any is.
- **Private profiles:** profile page, follow lists, reviews and followed-score lines are hidden from
  others; their scores still count in rankings and theme stats.
- **Deleting a user cascades** to everything they own (ratings → reviews → reports, favorites,
  follows, profile, sessions).
- `theme.slug` is AnimeThemes' slug (`OP1`, `ED2`); with `anime.slug` it builds the watch link.
- `anime.anilist_id` / `mal_id` come from AnimeThemes' external resources — the hook for a future
  AniList/MAL list import, no AniList call needed.
- Cover images are **AnimeThemes' URLs** (their R2 bucket), not copies. See the open question in
  [data-sources.md](data-sources.md).

## Auth

- Better Auth with Discord + Google only; email/password is off
  ([decisions.md #3](decisions.md#3-social-login-only-username-picked-on-onboarding)).
- Account linking is on for both providers: same verified email → same user.
- The `username` plugin adds `user.username` (unique, lowercased) and `display_username`.
- **Onboarding gate:** `routes/__root.tsx` `beforeLoad` loads the session on every navigation and
  redirects a signed-in user with no username to `/onboarding`. The username becomes `/u/<name>`.
- `features/auth/server.ts`: `getCurrentUser` (server function, for routes) and `getSessionUser` /
  `requireUserId` (server-only, for other server functions).

## What bites

- **Plain exported helpers in `features/*/server.ts` break the client build** (`import-protection`).
  Use `createServerOnlyFn` ([decisions.md #7](decisions.md#7-server-only-helpers-are-createserveronlyfn-not-plain-functions)).
- **Drizzle upsert `set` keys are TS field names** (`titleRomaji`), not column names. An unknown key
  is **silently ignored** and the column never updates. The importer's `updateFromExcluded` is
  typed against the table's fields for this reason.
- **Changing auth plugins changes the schema.** After editing `src/lib/auth.ts`, regenerate
  `schema/auth.ts` (command in its header) and run `db:generate`.
- **Ranking a theme's position** (`findThemeDetail`) runs the full all-time and season rankings
  and looks the theme up. Fine while only rated themes are ranked; revisit with a real user base.
- **The importer never deletes.** A theme removed upstream stays here (with its ratings). Cleaning
  that up is a manual, deliberate operation.
